# Valyria Web App

نسخهٔ مستقل برای شروع سیزن آینده، بر پایهٔ نسخهٔ `505510aed899d60de44cfb44205650e073d43158` بازی. دادهٔ بازیکنان فعلی منتقل نشده است. آخرین نقشه، مدل‌های ارتش، نهادها، فروشگاه و تنظیم سیزن در کد مشترک وجود دارند.

## امکانات مستقل

- ساخت حساب با نام کاربری و رمز، سپس ساخت کاراکتر و درخواست خاندان از همان روند بازی.
- ورود با کوکی HttpOnly، نشست چهارده‌روزه با ساعت واقعی، خروج و تغییر رمز همراه با ابطال نشست‌های قدیمی.
- کد بازیابی یک‌بارمصرف؛ پس از بازیابی، کد تازه صادر می‌شود. هیچ سرویس تلگرام، ایمیل، پیامک یا OTP خارجی برای ورود لازم نیست.
- صندوق اعلان با فیلتر، جست‌وجو، خواندن تکی و گروهی، صفحه‌بندی، بایگانی و بازگرداندن؛ نامهٔ خصوصی و توییت‌ها هم باقی‌اند.
- اعلان‌های سیستم در دیتابیس خود بازی ذخیره می‌شوند. تنظیمات قدیمیِ خاموش‌کردن بات یا کلاغ مانع ثبت اعلان سیستم در نسخهٔ وب نیستند. اعلان‌های صف‌دار خانواده، پروژه و نبرد از ذخیره‌سازی موجودشان استفاده می‌کنند و تکراری درج نمی‌شوند.
- وب‌اپ قابل نصب با نام Valyria Web App، آیکن، صفحهٔ قطع اتصال و کش محدود فایل‌های ثابت. دادهٔ حساب و پاسخ API کش نمی‌شوند؛ خرید و انتقال در حالت قطع اتصال به صف ارسال مجدد نمی‌روند.

اعلان داخل اپ به معنی تضمین اعلان هنگام بسته بودن برنامه نیست. این نسخه به سرویس پوش خارجی متکی نیست. پس از بازشدن اپ اعلان‌های ذخیره‌شده دریافت می‌شوند و هنگام بازبودن، صندوق و شمارنده دوره‌ای تازه می‌شوند.

## نصب روی سرور داخلی تازه

### مسیر ساده برای اولین راه‌اندازی

از میزبان یک سرور لینوکسی مستقل با IP عمومی و Docker Engine و افزونهٔ Docker Compose آماده بخواهید. پورت‌های وب ۸۰ و ۴۴۳ باید باز باشند. برای این نسخه نیازی به خرید هاست جداگانهٔ سایت، دیتابیس جدا یا سرویس تلگرام نیست. ظرفیت مناسب باید با تعداد کاربران و آزمون بار مشخص شود؛ برای شروع و آزمون اولیه، سرور کوچک قابل ارتقا انتخاب کنید.

یک دامنه یا زیردامنه تهیه کنید؛ اگر شرکت میزبان زیردامنهٔ قابل استفاده می‌دهد، دامنهٔ اختصاصی ضروری نیست. آدرس را در تنظیمات DNS به IP سرور متصل کنید. برای نصب وب‌اپ روی گوشی، HTTPS معتبر لازم است.

پوشهٔ همین نسخه را در یک مسیر تازه مانند `/opt/valyria-web-app` آپلود کنید. فایل‌های `.env`، دیتابیس، `node_modules` و اطلاعات نسخهٔ تلگرامی را انتقال ندهید. سپس در ترمینال سرور وارد پوشه شوید و آدرس واقعی خود را به راه‌انداز بدهید:

```sh
cd /opt/valyria-web-app
bash deploy/setup-web-app.sh play.yourdomain.ir
```

راه‌انداز تنظیمات اولیه را می‌سازد و سایت، سرور بازی، دیتابیس و HTTPS را بالا می‌آورد. در اجرای بعدی تنظیمات موجود را نگه می‌دارد؛ اگر اتصال دیتابیس با این استقرار مستقل سازگار نباشد متوقف می‌شود. صدور گواهی فقط با DNS صحیح و دسترسی لازم انجام می‌شود؛ پیام آماده‌بودن سرویس‌ها به‌تنهایی تأیید دسترسی عمومی نیست.

فقط بار اول، حساب مدیر اصلی را بسازید:

```sh
docker compose exec backend python -m web_auth bootstrap-admin
```

نام کاربری و رمز دلخواه را همان‌جا وارد کنید و کد بازیابی را نگه دارید. سپس آدرس بازی را در مرورگر باز کنید، با حساب مدیر وارد شوید و تنظیمات سیزن را انجام دهید. قبل از شروع سیزن، پشتیبان‌گیری روزانهٔ دیتابیس و نگهداری یک نسخه خارج از سرور را با میزبان تنظیم کنید.

این راه‌انداز هنوز روی سرور داخلی واقعی اجرا نشده است. ساخت اولیه به دانلود بسته‌ها و ایمیج‌ها نیاز دارد؛ در صورت قطع اینترنت بین‌الملل، باید این وابستگی‌ها از قبل آماده یا از مخزن داخلی قابل دریافت باشند. استقرار داخلی همچنین به معنی تضمین دسترسی همهٔ اپراتورها نیست و باید از اینترنت کاربران بررسی شود.

### تنظیم دستی

۱. همین شاخه را در مسیر مستقل مانند `/opt/valyria-web-app` دریافت کنید. برای دیتابیس یا پوشهٔ داده از مسیر نسخهٔ تلگرامی استفاده نکنید.

۲. از `.env.example` یک `.env` بسازید. `APP_HOST` و `PUBLIC_APP_ORIGIN` را با آدرس واقعی جایگزین کنید؛ دومی باید دقیقاً مبدأ HTTPS بازی باشد و مسیر اضافه نداشته باشد. نام دیتابیس پیش‌فرض `valyria_web_app` است. `WEB_COOKIE_SECURE=true` در انتشار عمومی حفظ شود.

۳. اجرا:

```sh
docker compose up -d --build
docker compose exec backend python -m web_auth bootstrap-admin
```

دستور دوم نام کاربری و رمز ادمین اصلی را در ترمینال می‌پرسد. اولین ثبت‌نام عمومی هیچ دسترسی ادمینی نمی‌گیرد. پس از ایجاد ادمین اصلی، بوت‌استرپ بسته می‌شود. رمز و کد بازیابی را در گیت یا چت عمومی قرار ندهید.

۴. وارد حساب ادمین شوید، شماره و نام سیزن، ظرفیت اقلیم‌ها و قواعد را بررسی کنید. اطلاعات بازی جدید از این محیط ساخته می‌شوند؛ چیزی از دیتابیس فعال کپی نمی‌شود.

دیتابیس Docker در volume مستقل همین پروژه ذخیره می‌شود و پورت آن عمومی نشده است. فایل‌های نقشه، فونت و تصاویر از همان سرور ارائه می‌شوند. برای نصب عمومی PWA، HTTPS معتبر لازم است؛ دامنهٔ مستقل یا زیردامنهٔ مناسب میزبان قابل استفاده است. فایل Vercel مربوط به نسخهٔ تلگرامی در این استقرار استفاده نمی‌شود.

## بازیابی مدیریتی رمز

بازیکن با نام کاربری و کد بازیابیِ خودش از صفحهٔ بازیابی وارد می‌شود. اگر کد هم گم شده باشد، مدیریت باید بیرون از این فرایند هویت را بررسی کند و سپس روی سرور اجرا کند:

```sh
docker compose exec backend python -m web_auth reset-password
```

این دستور رمز و کد تازه صادر می‌کند و نشست‌های قبلی را باطل می‌کند. کد یا رمز تازه فقط به صاحب تأییدشدهٔ حساب تحویل داده شود. این مسیر یک دسترسی عمومی یا رمز پشتیِ وب ندارد.

## حفظ هر دو نسخه

کد این نسخه در شاخهٔ `codex/valyria-web-app` و کد تلگرام در `new-design` نگهداری می‌شود. اصلاح مکانیک مشترک باید در هر دو نسخه بررسی و آزمایش شود. گیت به‌تنهایی دو شاخه را خودکار همگام نمی‌کند؛ همگام‌سازی کور یا کپی کامل شاخهٔ تلگرام، ورود مستقل و صندوق اعلان را خراب می‌کند.

برای هر تغییر مشترک، تغییر را در یک commit محدود نگه دارید، همان تغییر را به نسخهٔ دیگر منتقل کنید و اختلاف‌های اختصاصی را حفظ کنید. فایل‌های `auth.py`، `web_auth.py`، `telegram_bot.py`، ورودی اپ، نشست وب، service worker و تنظیم استقرار نقاط اختصاصی مهم‌اند. دستور کار نگهداری در `AGENTS.md` هر دو محل ثبت شده است.

این نسخه روی سرور فعلی منتشر نمی‌شود. قبل از استفادهٔ واقعی، پشتیبان‌گیری دیتابیس جدید، ظرفیت سرور، HTTPS، ایجاد حساب ادمین و آزمون نصب روی گوشی واقعی بررسی شوند. دریافت اولیهٔ ایمیج‌های Docker و بسته‌های ساخت به اینترنت یا مخزن داخلیِ آماده نیاز دارد؛ این فایل‌ها باید پیش از قطع احتمالی دسترسی در دسترس سرور باشند.

## اعتبارسنجی توسعه

ساخت رابط: `npm install && npm run build` در frontend. وابستگی‌های ساخت باید روی سرور یا مخزن داخلی موجود باشند.

آزمون ورود و صندوق با دیتابیس حافظه‌ای جدا: `pip install -r requirements-dev.txt` و سپس `python -m unittest tests.test_web_app` در backend؛ این آزمون را در پردازهٔ جدا اجرا کنید تا دیتابیس حافظه‌ای مستقل بارگذاری شود.

آزمون‌های مکانیک مشترک شامل نهادها، فروشگاه، سفر و کنترل لشکر نیز جدا اجرا شده‌اند. آزمون‌های قدیمی مخصوص احراز هویت تلگرام معیار ورود وب نیستند و باید با نشست مرورگر اجرا شوند. آزمون مرورگر توسعه، ورود و ثبت‌نام واقعی در سرور حافظه‌ای، کد بازیابی، صندوق، بایگانی، خروج، کوکی، service worker و صفحهٔ قطع اتصال را بررسی می‌کند. در آن مسیر، درخواست خارجی مشاهده نشده است. آزمون روی گوشی واقعی و MongoDB واقعیِ محیط نهایی جایگزین نشده است.

مراجع طراحی: [ذخیرهٔ رمز](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)، [نشست امن](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)، [پیشگیری از CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)، [نصب PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).


### نصب بدون دریافت بستهٔ نقشه

راهنمای `/?install=1` نصب از Chrome در اندروید و افزودن به صفحهٔ اصلی در Safari آیفون را توضیح می‌دهد. دریافت بستهٔ کامل نقشه لازم نیست و گزینهٔ آن حذف شده است. با فعال‌شدن نسخهٔ جدید، کش مخصوص بستهٔ قدیمی پاک می‌شود؛ حساب و داده‌های ورود دست‌نخورده می‌مانند. تصاویر و مدل‌های مورد نیاز هنگام نمایش دریافت می‌شوند. نمایش مرورگری همچنان به دریافت فایل‌های نمایشی نیاز دارد؛ این روش مانع استخراج آن فایل‌ها نیست.
