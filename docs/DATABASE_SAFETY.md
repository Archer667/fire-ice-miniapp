# محافظت از دیتابیس هنگام انتشار

نسخهٔ تلگرام و وب مستقل‌اند. هیچ پشتیبان یا اطلاعات حسابی نباید بین آن‌ها جابه‌جا شود.

## مسیر انتشار

1. ساخت پشتیبان از دیتابیس همان نسخه، با توقف کوتاه سرویس backend برای جلوگیری از نوشتن هم‌زمان.
2. بازیابی پشتیبان روی یک کانتینر موقت MongoDB با network=none، فضای دادهٔ موقت و بدون اتصال به volume اصلی.
3. مقایسهٔ تعداد اسناد مجموعه‌ها؛ مجموعه‌های دارای حذف خودکار زمانی از مقایسهٔ شمارشی مستثنا هستند.
4. دریافت فایل پشتیبان روی رایانهٔ مدیر و تطبیق SHA-256.
5. فقط پس از این مراحل، جایگزینی فایل‌های مجاز، ساخت ایمیج و بررسی محافظت آن انجام می‌شود.
6. فعال‌کردن backend و بررسی سلامت. هیچ حسابی هنگام انتشار ساخته، حذف یا بازنشانی نمی‌شود.

فایل‌های پشتیبان شامل اطلاعات خصوصی حساب‌ها هستند؛ آن‌ها را عمومی یا داخل گیت قرار ندهید. آرشیوهای سرور زیر /opt/valyria-database-backups با دسترسی محدود نگه داشته می‌شوند. نسخهٔ خارج از سرور نیز باید در محل امن نگهداری شود. بستهٔ کد جایگزین پشتیبان دیتابیس نیست.

## جداسازی تست

- ایمیج اصلی فاقد پوشهٔ tests و وابستگی‌های آزمایشی است.
- متغیر VALYRIA_RUNTIME در ایمیج اصلی production است.
- پیش از ساخت کلاینت دیتابیس، اجرای تست در محیط production رد می‌شود.
- تست‌های توسعه فقط از run_safe_tests.py استفاده می‌کنند. این اجراکننده پیش از import کد، کلاینت MongoDB را با کلاینت حافظه‌ای جایگزین می‌کند.
- تست مصرف غذا دیگر هیچ دیتابیسی را پاک نمی‌کند و دادهٔ مستقل خودش را در حافظه می‌سازد.

اجرای محلی:

    python -m pip install -r requirements-dev.txt
    python run_safe_tests.py tests.test_runtime_safety tests.test_urgent_food_recruit

دستورهای unittest و pytest را در کانتینر production اجرا نکنید. اجرای تست با دسترسی شبکه و اطلاعات اتصال دیتابیس اصلی ممنوع است.

## محدودیت‌ها

این محافظت مسیر اشتباه انتشار و اجرای تست روی دیتابیس اصلی را می‌بندد. دسترسی root سرور همچنان اختیار کامل دارد؛ این تغییر تضمین در برابر هر فرمان دستی، خرابی دیسک یا حمله نیست. بک‌آپ معتبر پیش از هر انتشار اجباری است و نگهداری نسخهٔ خارج از سرور ضروری است. این بسته داده‌های حذف‌شدهٔ قبلی را بازسازی نمی‌کند.
